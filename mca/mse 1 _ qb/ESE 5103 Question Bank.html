PART B: Answers (CO order)

CO1

Q1. Embedded boards. Types: microcontroller boards (LPC2148, Arduino, STM32 Nucleo), single-board computers (Raspberry Pi, BeagleBone), FPGA/CPLD boards, system-on-module boards, DSP boards, industrial/PLC boards. Seven factors: processing power and architecture, memory (flash/RAM), power consumption, peripherals and I/O count, connectivity (UART, SPI, I2C, USB, Ethernet), cost, tools/RTOS/community support. Also: form factor, operating temperature, reliability.

Q2. Toolchain. Source (.c/.s) -> compiler/assembler -> object files -> linker (with startup code and linker script/scatter file) -> .elf/.axf -> hex/bin converter -> flash programmer (ISP via UART bootloader, or JTAG) -> debugger/simulator. Draw as a horizontal flow of boxes.

Q3. ARM philosophy. Load/store RISC architecture, fixed 32-bit instructions, large register file (16 visible registers), conditional execution on every instruction, barrel shifter, simple low-power design. RISC: few simple instructions, one cycle each, register-to-register operations, hard-wired control, more code size. CISC: many complex variable-length instructions, memory-to-memory operations, microcoded control, smaller code, slower per instruction.

Q4. ARM7 modes (all 7 share R0-R7, CPSR; the mode is in CPSR bits 4:0).

Mode Entered by Use
User normal application code, unprivileged
FIQ fast interrupt fast handling, banks R8-R14
IRQ normal interrupt general interrupt handling
Supervisor reset, SWI OS/kernel, default after reset
Abort memory access fault data/prefetch abort
Undefined undefined instruction emulation
System software privileged, uses user registers

Each exception mode has its own banked SP, LR, and SPSR. Only FIQ banks R8-R12 too. Draw CPSR with N Z C V, I F T bits and mode field.

Q5. Data path. 3-stage pipeline (fetch, decode, execute). Blocks: instruction pipeline and decoder, register bank (31 registers) with two read ports and one write port, barrel shifter on operand B, ALU, 32x8 multiplier, address register with incrementer, data-in and data-out registers, control logic. Flow: register bank -> barrel shifter -> ALU -> result back to register bank or address register.

Q6. Instructions.

  • LDMIA R0!,{R2-R5}: load multiple, increment after. R2=[R0], R3=[R0+4], R4=[R0+8], R5=[R0+12]. ! writes back R0 = R0+16.
  • STMDB R2,{R5-R9}: store multiple, decrement before. Address starts at R2-20; R5 stored lowest, R9 highest. No writeback (no !), so R2 is unchanged.
  • SWI: software interrupt. Copies CPSR to SPSR_svc, saves return address in LR_svc, enters Supervisor mode, jumps to vector 0x08.
  • MRS R0,CPSR: copy CPSR (or SPSR) into a general register for reading.
  • MSR CPSR_c,R0: write to CPSR fields; used to change mode or mask IRQ/FIQ.

Q7. LPC2148 architecture. ARM7TDMI-S core, 512 KB flash, 32 KB SRAM (+8 KB USB RAM), VIC, PLL, two 10-bit ADCs (14 channels), 10-bit DAC, 2 timers, PWM, 2 UARTs, 2 I2C, SPI/SSP, RTC, watchdog, USB 2.0, up to 45 fast GPIO. Blocks connect over AHB (fast: flash, RAM, VIC) and the VPB bridge (slower peripherals).

Q8. Memory map.

Region Address
Flash 512 KB 0x0000_0000 to 0x0007_FFFF
On-chip SRAM 32 KB 0x4000_0000 to 0x4000_7FFF
USB DMA RAM 8 KB 0x7FD0_0000 to 0x7FD0_1FFF
Boot block 8 KB 0x7FFF_E000 to 0x7FFF_FFFF
VPB peripherals 0xE000_0000 to 0xE00F_FFFF
AHB peripherals (VIC at 0xFFFF_F000) 0xF000_0000 to 0xFFFF_FFFF

Q9. Crystal and reset. Crystal (10-25 MHz, typically 12 MHz) connects to XTAL1/XTAL2 with two ~22 pF capacitors to ground; the on-chip oscillator drives the PLL and CCLK. Reset: RST pin is active low with a Schmitt-trigger input; external RC (e.g. 10 k and 10 uF) gives power-on reset, and a push button to ground gives manual reset. After reset the PC = 0x0, core is in Supervisor mode, IRQ and FIQ are disabled, and the PLL is bypassed.

Q10. PLL multiplies the crystal to a higher CPU clock. Rules: CCLK = M x Fosc; FCCO = CCLK x 2 x P must lie between 156 and 320 MHz. For 12 MHz -> 60 MHz: M = 5, P = 2, so FCCO = 240 MHz. Registers: PLL0CON (bit0 PLLE enable, bit1 PLLC connect), PLL0CFG (MSEL bits 4:0 = M-1, PSEL bits 6:5), PLL0STAT (bit 10 PLOCK), PLL0FEED (0xAA then 0x55 to make changes take effect).

#include <lpc214x.h>

void PLL_Init(void)
{
    PLL0CFG = 0x24;     // MSEL = M-1 = 4 (bits 4:0) -> M = 5; PSEL = 01 (bits 6:5) -> P = 2
                        // so 0x04 | (0x01 << 5) = 0x24; CCLK = 5 x 12 MHz = 60 MHz, FCCO = 240 MHz
    PLL0CON = 0x01;     // PLLE = 1: enable the PLL (not yet connected to the CPU)
    PLL0FEED = 0xAA;    // feed sequence part 1: the PLL ignores writes without both feeds
    PLL0FEED = 0x55;    // feed sequence part 2: PLL0CFG and PLL0CON now take effect

    while (!(PLL0STAT & (1 << 10)));  // wait for PLOCK (bit 10): PLL has locked on 240 MHz

    PLL0CON = 0x03;     // PLLE = 1 and PLLC = 1: connect the PLL output as the system clock
    PLL0FEED = 0xAA;    // feed again so the connect takes effect
    PLL0FEED = 0x55;

    VPBDIV = 0x01;      // peripheral clock = CCLK / 1 = 60 MHz (default is CCLK / 4 = 15 MHz)
}

Order matters: configure, enable, feed, wait for lock, connect, feed. Connecting before lock crashes the clock.

Q11. GPIO. LPC2148 has Port 0 (P0.0-P0.31) and Port 1 (P1.16-P1.31). Pins are shared with peripherals, so select GPIO first.

  • PINSELx: 2 bits per pin, 00 = GPIO.
  • IODIRx: 1 = output, 0 = input.
  • IOSETx: writing 1 drives the pin high; writing 0 does nothing.
  • IOCLRx: writing 1 drives the pin low; writing 0 does nothing.
  • IOPINx: reading gives the pin state; writing sets the whole port.

Q12. Interrupt vs polling. Polling: CPU repeatedly checks a flag, simple but wastes cycles and reacts late. Interrupt: device signals the CPU, which runs an ISR then resumes; efficient and fast response, needs VIC setup. Level-triggered: the interrupt stays active while the line is at the level (low/high), so the source must be cleared or it re-fires. Edge-triggered: fires once on a transition (rising/falling), latched, so short pulses are not missed.

Q13. Pull-up/pull-down. A pull-up resistor ties an input to Vcc so it reads 1 when the switch is open (switch to ground reads 0, active low). A pull-down ties it to ground so it reads 0 when open (switch to Vcc reads 1). They prevent a floating input picking up noise. Typical values 4.7 k to 10 k.

Q14. Palindrome.

#include <stdio.h>

int isPalindrome(char *s)
{
    int i = 0, j = 0;
    while (s[j] != '\0') j++;      // move j to the end to find the string length
    j--;                           // j now points at the last real character
    while (i < j)                  // compare from both ends toward the middle
    {
        if (s[i] != s[j])          // first mismatch means not a palindrome
            return 0;
        i++;                       // move left pointer right
        j--;                       // move right pointer left
    }
    return 1;                      // all pairs matched
}

int main(void)
{
    char str[] = "madam";          // received string (stored in a buffer)
    if (isPalindrome(str)) { /* palindrome */ }
    else                   { /* not palindrome */ }
    while (1);
}

Q15. EINT1 switch with LED P1.18. EINT1 is on P0.3 (PINSEL0 bits 7:6 = 11) and VIC channel 15. Switch is normally high, so use falling-edge sensitivity.

#include <lpc214x.h>

void delay_ms(unsigned int ms);          // defined in Q16

void EINT1_ISR(void) __irq               // __irq makes the compiler save/restore registers
{
    IOSET1 = (1 << 18);                  // LED on (P1.18 active high)
    delay_ms(1000);                      // stay on for one second
    IOCLR1 = (1 << 18);                  // LED off
    EXTINT = 0x02;                       // write 1 to bit 1 to clear the EINT1 flag
    VICVectAddr = 0;                     // tell the VIC the interrupt is finished
}

int main(void)
{
    PLL_Init();                          // Q10: 60 MHz CCLK and PCLK
    IODIR1 |= (1 << 18);                 // P1.18 as output
    IOCLR1  = (1 << 18);                 // LED starts off
    PINSEL0 |= (3 << 6);                 // P0.3 -> function 11 = EINT1
    EXTMODE  |= 0x02;                    // EINT1 edge sensitive
    EXTPOLAR &= ~0x02;                   // falling edge (switch press pulls line low)
    VICIntSelect &= ~(1 << 15);          // channel 15 is IRQ, not FIQ
    VICVectCntl0 = 0x20 | 15;            // slot 0 enabled (bit 5) and mapped to channel 15
    VICVectAddr0 = (unsigned long)EINT1_ISR; // slot 0 jumps to our ISR
    VICIntEnable = (1 << 15);            // enable the EINT1 interrupt in the VIC
    while (1);                           // idle; all work is in the ISR
}

CO2

Q16. Timers. LPC2148 Timer0/Timer1 are 32-bit with a prescaler. Registers: TCR (bit0 enable, bit1 reset), CTCR (0 = timer mode), PR (prescaler maximum), TC (timer counter, counts +1 every PR+1 PCLK cycles), MCR/MR0 (match actions), IR (flags). With PCLK = 60 MHz, set PR = 59 so TC counts once per 1 us.

#include <lpc214x.h>

void delay_us(unsigned int us)
{
    T0CTCR = 0x00;          // timer mode: TC increments from the prescaled PCLK
    T0PR   = 59;            // PR = 60 MHz/1 MHz - 1 = 59 -> 1 tick = 1 us
    T0TCR  = 0x02;          // bit1 = 1: hold TC and PC in reset
    T0TCR  = 0x01;          // bit0 = 1, bit1 = 0: release reset and start counting
    while (T0TC < us);      // busy-wait until TC reaches the requested microseconds
    T0TCR  = 0x00;          // stop the timer
}

void delay_ms(unsigned int ms)
{
    while (ms--)            // repeat once per millisecond
        delay_us(1000);     // 1000 us = 1 ms
}

Q17. 1 ms and 1 us: delay_us(1) gives 1 us (function overhead means very short values are approximate) and delay_ms(1) gives 1 ms, both using the code above. For a more exact ms delay, set T0PR = 59999 so one tick is 1 ms and wait for T0TC < ms.

Q18. LED P0.5, 50 ms on / 50 ms off. Circuit: P0.5 -> 330 ohm resistor -> LED anode; LED cathode -> GND (active high).

int main(void)
{
    PLL_Init();                  // 60 MHz CCLK/PCLK (Q10) so the timer maths is right
    PINSEL0 &= ~(3 << 10);       // P0.5 uses bits 11:10; 00 = GPIO
    IODIR0  |=  (1 << 5);        // P0.5 as output
    while (1)
    {
        IOSET0 = (1 << 5);       // LED on
        delay_ms(50);            // 50 ms from Q16
        IOCLR0 = (1 << 5);       // LED off
        delay_ms(50);
    }
}

Q19. DAC (theory). 10-bit resistor-string DAC, output AOUT on P0.25 (PINSEL1 bits 19:18 = 10). One register, DACR: VALUE in bits 15:6, BIAS bit 16 (0 = settling 1 us, 700 uA; 1 = 2.5 us, 350 uA). Output: Vout = (VALUE / 1024) x VREF. Waveforms by changing VALUE in a loop: sawtooth: count 0 to 1023 and wrap to 0; square: alternate between 0 and 1023 with a delay; triangle: count up to 1023, then down to 0. Frequency is set by the delay between steps.

Q20. ADC (theory). Ten characteristics: resolution, sampling rate, conversion time, input voltage range/VREF, accuracy (offset and gain error), INL, DNL, quantisation error, SNR/ENOB, number of channels, power consumption, input impedance, architecture (SAR, flash, sigma-delta), interface. LPC2148 has 10-bit SAR ADCs. Burst mode: ADCR is set with SEL = channel 7 mask (bit 7), CLKDIV so ADC clock is at most 4.5 MHz (60/(13+1) = 4.3 MHz), BURST bit 16 = 1 (repeated conversions without START), CLKS = 000 (10-bit, 11 clocks), PDN bit 21 = 1, START bits 26:24 = 000. Result is read from AD1DR7 (bits 15:6), valid when DONE bit 31 = 1.

CO3

Q21. CPOL and CPHA. CPOL sets the idle clock level: 0 = low, 1 = high. CPHA sets the sampling edge: 0 = data sampled on the first (leading) clock edge, 1 = on the second (trailing) edge. This gives modes 0 to 3; master and slave must use the same mode. LPC2148: S0SPCR bit 3 = CPHA, bit 4 = CPOL. Draw SCK, MOSI, MISO for each mode with sampling arrows.

Q22. SPI clock and multi-slave. Master generates SCK = PCLK / S0SPCCR (value even, at least 8). Master has one shared SCK, MOSI, MISO and one slave-select line per slave (active low). Only the selected slave drives MISO; others tri-state. Diagram: one master with three slaves, SS1/SS2/SS3 from three GPIO pins.

Q23. SPI master sends 'M'. SPI0 pins: SCK0 P0.4, MISO0 P0.5, MOSI0 P0.6, chip select on P0.7 used as plain GPIO.

void SPI_MasterInit(void)
{
    PINSEL0 |= 0x00005500;      // 01 on bits 15:8: P0.4 SCK0, P0.5 MISO0, P0.6 MOSI0, P0.7 SSEL0
    PINSEL0 &= ~(3 << 14);      // override P0.7 back to GPIO, used as manual chip select
    IODIR0  |= (1 << 7);        // P0.7 output
    IOSET0   = (1 << 7);        // slave deselected (active low)
    S0SPCCR  = 8;               // SCK = 60 MHz / 8 = 7.5 MHz (8 is the minimum, must be even)
    S0SPCR   = 0x20;            // bit5 MSTR = 1 master; CPOL = 0, CPHA = 0 (mode 0)
}

void SPI_Send(char c)
{
    IOCLR0 = (1 << 7);          // select slave
    S0SPDR = c;                 // writing the data register starts the transfer
    while (!(S0SPSR & 0x80));   // wait for SPIF (bit 7): transfer complete
    (void)S0SPDR;               // reading SPSR then SPDR clears SPIF
    IOSET0 = (1 << 7);          // deselect slave
}

int main(void) { PLL_Init(); SPI_MasterInit(); SPI_Send('M'); while (1); }

Slave side:

S0SPCR = 0x00;                  // MSTR = 0: slave mode, same CPOL/CPHA as master
while (!(S0SPSR & 0x80));       // wait for the master's clock to shift in a byte
char r = S0SPDR;                // read the received 'M' (also clears SPIF)

Q24. I2C. Two open-drain wires, SDA and SCL, each with a pull-up (about 4.7 k). Multi-master, addressed protocol. Frame: START (SDA falls while SCL high) -> 7-bit address + R/W bit -> ACK from slave (SDA pulled low) -> data byte -> ACK ... -> STOP (SDA rises while SCL high). Data on SDA changes only while SCL is low and is sampled while SCL is high. Speeds: 100 kHz, 400 kHz, 3.4 MHz.

Q25. Arbitration. Bus is wired-AND, so a 0 always wins. Two masters start together; each sends bits and reads SDA back. A master that sends 1 but reads 0 has lost: it stops driving and switches to slave/listening, with no data corrupted. The master with the lower address/data wins. Clocks are also synchronised: SCL is low as long as the slowest master holds it low.

Q26. Bit banging. Implementing a serial protocol (SPI, I2C) in software by toggling GPIO pins with delays instead of using the hardware peripheral. Useful when pins or peripherals are unavailable; slower and uses CPU time.

void SPI_BitBang(unsigned char d)
{
    for (int i = 0; i < 8; i++)
    {
        if (d & 0x80) IOSET0 = (1 << 6); else IOCLR0 = (1 << 6); // put MSB on MOSI (P0.6)
        IOSET0 = (1 << 4);                                       // SCK high: slave samples the bit
        IOCLR0 = (1 << 4);                                       // SCK low
        d <<= 1;                                                 // next bit
    }
}

Extra practice solutions

X1. Blink P0.5 (software delay).

#include <lpc214x.h>

void delay(void) { volatile unsigned long i; for (i = 0; i < 500000; i++); } // volatile stops the compiler removing the loop

int main(void)
{
    PINSEL0 &= ~(3 << 10);   // P0.5 as GPIO
    IODIR0  |=  (1 << 5);    // bit 5 = 1: output
    while (1)
    {
        IOSET0 = (1 << 5);   // writing 1 to IOSET sets P0.5 high; other pins untouched
        delay();
        IOCLR0 = (1 << 5);   // writing 1 to IOCLR sets P0.5 low; other pins untouched
        delay();
    }
}

X3. Switch P0.4 (active low) controls LED P0.5.

int main(void)
{
    PINSEL0 &= ~((3 << 8) | (3 << 10));  // P0.4 and P0.5 as GPIO
    IODIR0  &= ~(1 << 4);                // P0.4 input (switch)
    IODIR0  |=  (1 << 5);                // P0.5 output (LED)
    while (1)
    {
        if (!(IOPIN0 & (1 << 4)))        // IOPIN0 reads pin levels; bit 4 low = pressed
            IOSET0 = (1 << 5);           // pressed: LED on
        else
            IOCLR0 = (1 << 5);           // released: LED off
    }
}

X4. Toggle on press with debounce.

int main(void)
{
    IODIR0 &= ~(1 << 4);  IODIR0 |= (1 << 5);   // P0.4 in, P0.5 out
    while (1)
    {
        if (!(IOPIN0 & (1 << 4)))               // press detected
        {
            delay_ms(20);                       // wait out contact bounce
            if (!(IOPIN0 & (1 << 4)))           // still low: a real press
            {
                if (IOPIN0 & (1 << 5)) IOCLR0 = (1 << 5);   // LED on -> turn off
                else                   IOSET0 = (1 << 5);   // LED off -> turn on
                while (!(IOPIN0 & (1 << 4)));   // wait for release so one press = one toggle
            }
        }
    }
}

Hints: X2: IODIR1 = 0x00FF0000, then for each LED IOSET1 = (1<<(16+i)); delay; IOCLR1 = (1<<(16+i));. X5: IOSET1 = 0x000F0000 / IOCLR1 = 0x000F0000. X6: IOCLR1 = 0x00FF0000; IOSET1 = (count << 16); for count = 0 to 255, clearing first so stale bits go away.
